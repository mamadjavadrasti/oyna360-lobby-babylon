# ارتباطات استاندارد لابی: متن و تماس زندهٔ گروه دوستان

از نسخهٔ `0.3.0`، `PlatformLobby` در iframe اوینا برای ارتباطات انسانی از سرویس communications استفاده می‌کند. رندر آواتار، حرکت و `lobby:data` همچنان مسیر خودشان را دارند.

| کانال | مخاطبان | رفتار پیش‌فرض |
|---|---|---|
| `text` | بازیکنان همان instance لابی | بعد از welcome متصل می‌شود؛ روی سرویس ارتباطات ذخیره می‌شود |
| `voice-party` | اعضای پذیرفته‌شدهٔ دورهمی خصوصیِ انتخاب‌شده | تماس زنده فقط با کلیک میکروفون؛ انتخاب پیش‌فرض ویس |
| `voice-lobby` | حاضران همان instance لابی که خودشان به تماس آمده‌اند | اختیاری و پیش‌فرض در UI مخفی |
| `lobby:data` | دادهٔ کنترل/همگام‌سازی بازی | مستقل از متن و صوت؛ پیام کاربر را در این کانال نفرستید |

تماس خصوصی «هرکسی در لابی که جزو دوستانم است» نیست؛ یک **گروه مشخص با عضویت تأییدشده** است. افراد دعوت‌شده باید دعوت دورهمی را قبول کنند. کاربران نامرتبط با بودن در همان بازی وارد تماس گروه نمی‌شوند.

## اتصال استاندارد

```ts
const lobby = await PlatformLobby.create({
  canvas,
  platformInit,
  roomId: platformInit.lobby!.roomId,
  wsUrl: platformInit.lobby!.wsUrl,
  config: {
    enableChat: true,
    enableVoice: true,
    communications: {
      parentOrigin: 'https://oyna360.ir', // origin دقیق محیط واقعی خودتان
      allowLobbyVoice: false, // حالت پیش‌فرض: فقط گروه دوستان
    },
  },
});
lobby.on('error', ({ code, message }) => showToast(message));
```

وقتی داخل iframe اوینا هستید، تنظیم `communications` اختیاری است؛ origin پیش‌فرض از referrer والد خوانده می‌شود. بهتر است برای محیط تولید origin مورد اعتماد را صریح بدهید، مخصوصاً وقتی سیاست referrer آن را حذف می‌کند. خطای سرویس ارتباطات اجرای صحنه/آواتار/حرکت را متوقف نمی‌کند.

برای تماس خصوصی، از دورهمی دوستان با «بریم بازی» یا «پیوستن به بازی دوستان» وارد بازی شوید. والد اتاق خصوصیِ همراه این اجرای بازی را می‌شناسد. اگر گروهی انتخاب نشده باشد، کلیک میکروفون پیام راهنما می‌دهد؛ به تماس همگانی برنمی‌گردد. `enableVoice` فقط قابلیت/UI را فعال می‌کند و مجوز یا میکروفون را خودکار روشن نمی‌کند.

UI پیش‌فرض متن و دکمهٔ تماس را می‌سازد؛ اگر HUD اختصاصی ندارید هم دکمهٔ تماس در صفحه قرار می‌گیرد. برای UI اختصاصی:

```ts
// نمایش متن‌های تأییدشدهٔ سرور؛ پیام خود فرستنده هم از سرور echo می‌شود.
lobby.on('chat', ({ userId, displayName, text }) => appendChat({ userId, displayName, text }));
lobby.sendChat('سلام'); // boolean: پذیرش محلی برای ارسال؛ موفقیت نهایی از chat/error می‌آید

const voice = lobby.getVoiceChat();
const offVoice = voice?.onStateChange(({ active, muted, peerCount, mode }) => {
  updateCallUi({ active, muted, peerCount, mode });
});

// فقط در handler کلیک کاربر:
await voice?.enable('friends'); // در مسیر جدید یعنی تماس گروه خصوصی انتخاب‌شده
voice?.setMicMuted(true);
voice?.setMicMuted(false);
await voice?.disable();

// خروج از صحنه:
offVoice?.();
lobby.destroy(); // ترک تماس، قطع سوکت‌ها و توقف trackهای میکروفون
```

نام `friends` برای سازگاری API حفظ شده است؛ در مسیر communications مجوز از عضویت اتاق خصوصی می‌آید. نوسازی توکن و بازسازی peerها هنگام reconnect توسط SDK انجام می‌شود. خروج یا لغو مجوز اتصال، تماس را متوقف می‌کند و برای ورود دوباره باید خود کاربر اقدام کند.

## فعال‌کردن اختیاری تماس لابی

```ts
// هنگام create:
config: { communications: { parentOrigin: 'https://oyna360.ir', allowLobbyVoice: true } }

// پس از انتخاب صریح کاربر در UI اختصاصی:
await lobby.getVoiceChat()?.enable('all');
```

در این حالت گزینهٔ «اعضای لابی» هم در UI ظاهر می‌شود؛ انتخاب اولیه همچنان گروه دوستان است. دریافت میکروفون و ورود به تماس خودکار نیست. تماس mesh فعلی حداکثر **۸ شرکت‌کنندهٔ فعال** در هر اتاق صوتی دارد؛ برای اتاق صوتی بزرگ‌تر نیاز به SFU و طراحی جداگانه است.

## مجوز، کانال و سرویس

SDK از والد با پیام `oyna:lobby:communications:request` شامل `channel` و شناسهٔ واقعی لابی درخواست اتصال می‌کند. والد **origin و پنجرهٔ همان iframe** را کنترل می‌کند. برای متن/تماس لابی، سرور نشست بازی و حضور در همان اتاق را تأیید می‌کند؛ برای تماس دوستان، عضویت دورهمی خصوصی بررسی می‌شود. سپس فقط توکن ۱۵دقیقه‌ای همان اتاق به بازی می‌رسد. JWT حساب را داخل iframe قرار ندهید.

اتصال Socket.IO در namespace مستقل `/communications-live` است، روی origin سرویس `NEXT_PUBLIC_COMMS_URL`. اتاق‌های transport هم مستقل‌اند: `text:{roomId}`، `voice-party:{roomId}` و `voice-lobby:{roomId}`. `roomId` اتاق ارتباطات با شناسهٔ لابی بازی یکی نیست؛ والد نگاشت را می‌سازد و SDK نباید شناسهٔ آن را حدس بزند.

تنظیمات مدیر برای اتاق بازی/دوستان و voice، همچنین منع چت/ویس لابی هر کاربر، در سرور بررسی می‌شوند. عضویت، حضور لازم و مجوزها هر ۱۵ ثانیه نیز بازبینی می‌شوند. متن از پالایش کلمات و سقف ارسال سرویس communications عبور می‌کند (حداکثر ۱۰ پیام در دقیقه برای حساب). چون مخاطبان دوستان هستند، به معنی روشن بودن خودکار تماس یا ضبط دائمی نیست؛ صوت زنده ذخیره و به FFmpeg فرستاده نمی‌شود.

سرویس ارتباطات فعلی به حساب ثبت‌نام‌شده نیاز دارد؛ نشست مهمان بازی به‌تنهایی مجوز متن یا تماس این سرویس نیست.

## استقرار

- سرویس مستقل communications باید نسخهٔ جدید را اجرا کند و `/socket.io/` با WebSocket upgrade به همان سرویس پروکسی شود؛ فقط پروکسی `/api` کافی نیست.
- `NEXT_PUBLIC_COMMS_URL` آدرس HTTPS پایهٔ API این سرویس است؛ SDK origin سوکت را از آن می‌گیرد. مسیر فعلی Socket.IO استاندارد `/socket.io/` است.
- `CORS_ORIGINS` سرویس باید origin دقیق پلتفرم و بازی‌های مجاز را شامل شود.
- برای تماس روی شبکه‌های محدود و موبایل، TURN لازم است. روی سرویس `COMMS_TURN_URLS` (آدرس‌های turn/turns با جداساز کاما) و `COMMS_TURN_SECRET` (secret مشترک coturn REST) تنظیم کنید. سرور credential موقت ۳۰دقیقه‌ای می‌سازد؛ secret به مرورگر داده نمی‌شود. بدون TURN اتصال فقط در شبکه‌هایی برقرار می‌شود که مسیر مستقیم/STUN جواب بدهد.
- صوت با WebRTC میان peerها یا از طریق TURN جابه‌جا می‌شود؛ سرور communications فقط signaling و مجوز را مدیریت می‌کند.
- رجیستری تماس فعلی در حافظهٔ **یک پردازش communications** است. برای این نسخه یک replica اجرا کنید؛ اجرای چند worker به registry/pubsub مشترک نیاز دارد. sticky session به‌تنهایی اعضای یک اتاق را کنار هم قرار نمی‌دهد.

این مسیر تماس زنده است. `/sdk/oyna-communications.js` همچنان API پیام صوتی ضبط‌شدهٔ دورهمی را ارائه می‌کند؛ `toggleRecording()` را به‌جای اتصال تماس زنده استفاده نکنید.

## توسعهٔ مستقیم و سازگاری

در top-level بدون والد، `communications` را با `getCredentials(channel, lobbyRoomId)` بدهید. این callback باید از میزبان مورد اعتماد، توکن محدود همان اتاق و مشخصات `{ baseUrl, roomId, userId, token, expiresIn }` را بگیرد. secret حساب را در کد بازی نگذارید. مسیر کامل با والد اوینا ساده‌ترین مسیر تست واقعی است.

`communications: false` مسیر قدیمی متن/WebRTC روی `/lobby` را نگه می‌دارد؛ برای اتصال جدید از آن استفاده نکنید. در top-level بدون تنظیمات communications، همین مسیر قدیمی برای سازگاری باقی می‌ماند؛ private-group جدید به والد یا credential provider نیاز دارد. `createDev()` آفلاین هم به این سرویس وصل نمی‌شود.

پکیج‌های `lobby-sdk` و `lobby-babylon` این تغییرات نسخهٔ `0.3.0` دارند و باید با هم build/منتشر/نصب شوند؛ تغییر سورس، بازی‌های نصب‌شده روی نسخهٔ قبلی npm را خودکار به‌روز نمی‌کند.

## بررسی توسعه در همین مخزن

```sh
node --test scripts/test-lobby-avatar-contract.mjs scripts/test-lobby-live-communications.mjs
node scripts/test-lobby-voice-browser.mjs
```

تست مرورگر دو کاربر را با میکروفون آزمایشی به gateway واقعی Socket.IO محلی وصل می‌کند و دریافت بستهٔ صوتی دوطرفه، خاموش‌بودن اولیهٔ میکروفون، بسته‌بودن پیش‌فرض تماس همگانی و آزادشدن میکروفون هنگام خروج را بررسی می‌کند. مجوز اتاق در این harness ساختگی است و دیتابیس واقعی تغییر نمی‌کند؛ بررسی نهایی حساب‌ها، HTTPS و TURN روی استقرار واقعی همچنان جداست. روی ویندوز از Edge استفاده می‌شود؛ کانال مرورگر را با `TEST_BROWSER_CHANNEL` می‌توان تغییر داد.
